## 1. 产品概述

### 1.1 定位

Qbird（中文名“青鸟”，早期原型名 MuseChat）目标是成为一款轻巧、安全导向、开箱即用的本地优先局域网聊天工具。设备之间直接通信，不依赖托管中转服务器或账号服务；用户数据优先保存在本地。体验可参考微信、内网通和飞秋，但不复制其品牌素材或依赖其服务。隐私和安全是设计目标，开发测试版尚未通过独立安全审计，也不应宣称已达到生产级安全。

### 1.2 目标用户与场景

- 同一局域网中的团队成员：发现同事、核实身份、单聊、群聊和传送文件。
- 个人用户：即使没有其他联系人，也可使用自聊保存个人记录。
- 对数据控制和跨平台有需求的小团队：自主部署、备份和恢复，不依赖第三方中转。

### 1.3 目标和非目标

**目标**：先完成 Windows 上身份、局域网发现、基础聊天与本地持久化的可靠闭环，核心保持轻巧并尽量开箱即用；基础架构与必要基础功能之外，长期方向是以插件扩展能力，避免为每种场景持续膨胀核心。扩展格式的侧边栏文件预览、AI Bot 接入等是插件路线图示例，不等于本阶段已实现或承诺交付；架构从一开始考虑跨平台与性能。

**非目标与边界**：不建设中转服务器；不承诺双方都离线时完成传输；不通过 MAC/IP 作为用户身份；当前不实现 Agent 联系人或插件市场。界面演示和底层代码不等于可用功能。

## 3. 核心产品规则

### 3.1 用户、身份和可信关系

1. 首次启动创建本地身份密钥；公钥指纹是稳定身份标识，IP、MAC 和设备名不是身份凭证。
2. 用户在首次引导中设置昵称、用户名与文件保存位置；头像、邮箱可选。资料与身份密钥分离，修改资料不改变身份。
3. **Qbird ID**：由身份公钥指纹派生的短标识（取 SHA-256 前 4 字节，显示为 `QB-XXXX-XXXX`）。ID 在安装后不变，用于在局域网中识别同一用户、区分重名；昵称和用户名可修改。ID 是展示与检索用的稳定标识，不替代完整指纹作为安全凭证。
4. **用户名**：本机填写、局域网内用于搜索的标识（2–20 位小写字母、数字、`-`、`_`）。用户名不保证全网唯一，重名时以 Qbird ID 区分；联系人列表与搜索结果必须同时展示用户名或 ID 摘要。
5. 发现结果和身份探测结果均不自动等同安全核验。默认交互为「局域网用户列表 → 一键添加」；添加后本机保存联系人，同时通过 TLS 证书证明的「联系人通知」请对方也加入你，实现**一方添加、双方互为联系人**（局域网工具惯例，不需要申请/通过流程）。
   - 对方默认自动接受；可在「我的资料 → 联系人添加」关闭自动接受，关闭后只在本机提示而不自动加入。
   - 对方离线时通知失败：本机联系人仍保存；下次打开与该联系人的单聊或手动「重新通知」时再次尝试。
6. 完整指纹核对为**可选增强**：需要更强确认时，用户可在联系人详情或发现页展开「身份详情」核对完整指纹并标记为已验证；未核对不影响本机添加，但界面必须区分「已添加」与「已核对指纹」。
4. 身份密钥异常、缺失、损坏或对方指纹变化时应明确提示，不得静默重建身份或自动信任变化；处理流程及用户文案待细化。
5. 每个系统用户对同一份数据只允许运行一个实例；不同系统用户和不同数据目录的边界按实际平台实现并验证。
6. 重新安装或迁移时，能用有效备份恢复原身份及所选数据；没有原身份备份时按新身份处理。备份不能保证恢复网络中已不存在的其他设备数据。

### 3.2 联系人

- 左侧“联系人”与“消息”分开；联系人包括单人联系人和群聊。
- 联系人中始终有“自己”，即使没有其他用户也可打开自聊；自聊为本地个人记录，不要求发现本机或对本机做指纹配对。
- 消息气泡里的引用显示被引用消息的发送者名称：优先群成员显示名，其次本机备注或联系人昵称，取不到时显示「群成员」等中性称呼，不显示指纹或 Qbird ID 片段。
- 联系人条目显示：头像（或首字色块）、昵称、`@用户名`、在线状态；详情显示 Qbird ID、备注、分组、添加方式、身份状态。用户名缺失（对方为旧版本或未填写）时显示 Qbird ID 摘要，不显示占位假名。
- 在线状态为尽力而为的提示：本机 mDNS 能发现该联系人，或其已保存地址在 350 ms 内可建立 TCP 连接，即显示「在线」，否则显示「离线」。每 10 秒后台刷新，也只在联系人、会话或当前单聊存在时刷新；不得宣称已读、活跃或身份已验证，地址可连不等于该地址就是本人。
- 收到对方添加请求（本机为待确认状态）时，联系人列表与侧栏都要显示该条目并标注「待确认」，提供「接受」「删除」；接受后转为已添加，删除只移除待确认请求，不影响已添加联系人与历史消息。自动接受关闭时不得让请求只能靠手动改库处理。
- 联系人搜索按昵称、用户名、备注、分组与 Qbird ID 匹配；搜索框提示“搜索用户名、昵称或备注”。
- 用户可为其他联系人设置仅本地使用的备注、按部门或自定义分组管理；支持拖拽进组，以及在联系人详情中选择分组。
- 联系人悬浮信息可按设置显示 IP、MAC 等；字段不可获得时不伪造，IP/MAC 仅供参考而不作为可信身份依据。MAC 的跨网段可见性与隐私提示待验证。
- 联系人确认、群聊及自身条目应清晰区分；“已添加”“已核对指纹”“等待对方添加”必须是不同状态，不得把未验证的发现候选显示为已信任。

### 3.3 会话列表与隐藏

1. 自聊、单聊和群聊统一采用会话列表规则：有消息的会话显示在消息列表，可从列表隐藏。
2. 隐藏是从消息列表移除显示，不删除联系人、群组或历史消息。用户仍可从联系人或群聊入口重新打开会话。
3. 对应会话出现新消息时重新显示；自聊在隐藏后再次给自己发送消息也重新显示。恢复后的排序、未读提示遵循统一消息列表规则。
4. 会话显示/隐藏状态与历史消息应持久化；重启不能丢失历史。隐藏入口位置、排序细节和未读计数策略待确认。
5. 空列表应明确提示，不能显示虚构联系人或消息。

### 3.4 消息与单聊

- 支持两名已核验身份的用户通过点对点加密连接发送和接收文字；明确连接状态、发送中、成功和失败，并允许在合理条件下重试。
- 消息在接收方可靠保存后再确认；重复投递不重复展示，消息 ID 冲突应拒绝并记录诊断信息。状态不可凭空显示成功。
- 本地保存会话和聊天记录，重启后可查看；断线/重连、对端离线、应用异常退出后的语义需实现并测试。
- 每条消息采用独立随机 ID；排序使用逻辑时钟与确定性平局规则，设备物理时间仅作显示。收到同一批消息的设备应得到一致顺序，并保留已知因果关系。
- 离线补发或迟到的消息按逻辑顺序插入历史，界面保持阅读锚点；无中转时无法保证各设备离线消息的真实发生时间顺序。
- 支持文字和图片出现在同一个消息气泡；图片、附件、文字的实际发送能力分阶段上线，不能用占位按钮冒充可用。
- Enter 默认发送，Shift+Enter 换行；发送/换行方式和自定义快捷键集中在设置页，输入区高度可上下调整。
- 输入区工具栏采用统一的线性图标：表情、图片、文件、截图、语音；发送按钮常驻右下，不随工具图标挤成文字按钮。表情以笑脸图标打开浮层面板（常用表情 + 我的表情），点击插入光标处；不再使用“表情”文字大按钮。
- 支持常用表情、本地表情包收藏及 GIF 等动态表情；具体格式、大小限制待确定。语音为后续能力时按钮置灰并标注，不得伪装可用。

### 3.5 群聊

- 群主创建群并邀请用户；群有稳定群 ID，局域网用户可按群名搜索并申请加入，也可接受群主邀请。
- 被拉进群默认需要本机确认：收到邀请后在「联系人 → 群聊邀请」中同意或拒绝，同意后才创建群与成员关系，拒绝会通知群主移除投递。设置中可勾选「被拉进群时自动加入」，勾选后邀请直接生效。
- 群成员可自主退出，群主可移除成员；显示成员列表及各自进群时间；群头像可设置。
- 退出群聊只结束成员关系，**历史消息保留在本机**，可从「联系人 → 已退出的群聊」只读查看和导出；只有用户主动删除记录才移除。
- 支持群消息引用并跳转到原消息；输入 @ 时显示可选择的成员列表。
- 支持群文件；引用群文件内容属于实验功能，设置开关默认关闭，不影响普通成员 @。
- 新成员仅可看到加入后的消息。成员离线期间由原发送者保存待投递消息，并在双方重新在线后补发；发送者不在线时无法保证补发。
- 权限验证、离线群成员同步细节和群主转让/解散等仍待设计，不宣称已支持。

### 3.6 文件、图片与离线传输

- 局域网点对点发送文件及图片；支持中断、断电及断线后的任务恢复与续传，验证文件完整性。
- 对方离线时，仅由本机保存待发送任务；双方重新在线后自动续传。双方都离线期间不发生传输，且不依赖中转服务器。
- 任务状态至少区分等待对方、传输中、暂停/中断、完成和失败；覆盖断电、文件变更、空间不足等异常，具体限额待定。
- 点击聊天图片可放大、缩放、旋转、拖拽；设置可选择独立查看（灯箱）或在右侧工作区打开。右侧工作区内的图片同样支持缩放、旋转、拖拽与复位。
- 附件在可收起、可调宽度的右侧工作区中以标签页打开，支持拖拽排序、左右分屏与重启恢复，规则见 3.6.1。HTML 须在受限环境中预览，防止任意脚本访问本地数据。

#### 3.6.1 右侧工作区（标签页）

**定位**

1. 右侧工作区是应用级面板，不属于某个会话：切换单聊、群聊、自聊或进入设置页时，已打开的标签保持存在，内容不重新加载。
2. 面板默认宽 420 px，可拖拽调整（320 px 至窗口宽度的 70%）。
3. 标签按内容去重：同一附件（按消息 ID）或同一规范化 URL 只保留一个标签，再次打开只激活已有标签。
4. 同时最多保留 12 个标签；超出时关闭最早的非当前标签并提示；标签可单个关闭、中键关闭、Ctrl+W 关闭当前，也可一次关闭全部。

**分屏与拖拽**

5. 标签栏分为左右两组；未分屏时只显示 A 组，开启分屏后 A/B 两组各占一半宽度并各自维护标签与激活项。
6. 标签可拖拽调整顺序；可拖到另一组的标签栏或空白区，实现跨组移动。松开前显示插入位置，拖动中的标签半透明。网页与 PDF 标签跨组移动时会重新载入内容，其余类型保持当前状态。
7. 某组没有标签时显示拖放占位提示；关闭分屏时 B 组标签按原顺序并入 A 组并保持最后一个为激活项。
8. 分屏状态与两组标签顺序属于工作区布局的一部分，随持久化保存与恢复。

**持久化**

9. 标签布局写入应用数据目录下的 `workspace.json`（上限 64 KiB，临时文件 + 重命名写入），不写入设置表，不记录任何文件字节、缩略图或网页内容。
10. 只持久化可重建的来源描述：单聊附件记录消息 ID 与文件名，群附件额外记录群 ID，网页记录规范化 URL；同时保存顺序、归属组、各组激活项、分屏状态、焦点组与面板宽度。
11. 启动（且未处于应用锁）时恢复；文件已被移动、删除、消息不可读或群成员身份失效时保留标签并明确提示不可预览，不静默移除。应用锁定时工作区隐藏，解锁后再恢复，避免面板覆盖锁屏。

**支持类型与边界**

12. 图片（png/jpg/jpeg/gif/webp/bmp）：单文件不超过 8 MiB；标签内提供缩放（滚轮以指针为中心）、旋转、拖拽、适应窗口、100% 与复位，双击在适应与 100% 间切换。
13. PDF：单文件不超过 64 MiB，扩展名必须为 `pdf` 且文件头匹配 `%PDF-`；使用 WebView2 内置 PDF 阅读器在沙箱外 iframe 中渲染。当前仅保证 Windows；内置阅读器不可用时必须显示「当前环境不支持内置 PDF 预览」并提供「用默认程序打开 / 打开所在目录」，不得伪装成可预览。
14. 文本（txt/log/csv/json/xml/ini/toml/yaml/yml）：上限 256 KiB，超过或二进制内容明确提示不可预览。
15. Markdown：按纯文本读取后在受限容器中渲染；HTML 在禁用脚本的沙箱 iframe 中预览。
16. 预览插件：按扩展名分派到已启用的只读插件，文件字节上限沿用插件上限（8 MiB）。
17. docx、xlsx、pptx 等 Office 格式当前不做内置渲染：在右侧工作区提示「暂不支持内置预览」，只提供「用默认程序打开 / 打开所在目录」，不自动拉起外部程序；安装预览插件后按插件能力处理。
18. 文件已被外部移动或删除时提示「文件已移动或删除」，不使用占位内容冒充预览。

**点击方式设置**

19. 设置页「工作区」提供「点击聊天文件时」：`在右侧工作区预览`（默认）或 `用默认程序打开`；存储键 `file_open_mode`。图片另由「点击聊天图片时」的灯箱/工作区选项（`image_open_mode`）控制，图片设置优先于文件设置。
20. 文件右键菜单保持「用默认程序打开 / 打开所在目录 / 预览 / 复制文件名」；其中「预览」始终进入右侧工作区，不受上述默认设置影响。

**网页链接**

21. 聊天正文与图片说明中的 `http://`、`https://` 链接可点击（`www.` 开头补全为 https），点击后在当前焦点组新建或激活网页标签。
22. 网页以 iframe 载入，沙箱仅允许脚本、同源（iframe 自身来源）与表单，禁止顶层跳转与弹窗，不发送 referrer；外部页面拿不到 Tauri IPC、聊天数据或本机路径。
23. 外部站点无法跨域探测是否禁止嵌入：6 秒内未完成加载时提示「页面可能禁止嵌入或在当前网络不可达」，并始终提供「在系统浏览器打开」。提示文案不得断言已成功加载。
24. 关闭标签时释放对应的 blob URL；「关闭全部」释放全部预览资源并清除持久化布局。

**安全边界**

25. 附件字节只从本机数据库记录的实际路径读取，路径由消息 ID 解析，不接受前端传入路径；预览不写回、不上传、不改动原文件。
26. 放宽 CSP 仅用于 `blob:` 与 http/https iframe；不放开脚本源、不放开 IPC 连接源。`workspace.json` 仅本机可读，内容视为不可信输入：恢复时校验类型、数量上限与 URL 协议，无法识别的条目直接忽略。
- 截图、拖拽与粘贴的完整规则见 3.14；截图结果只进入输入区暂存，不直接发送。
- 接收文件的保存位置与接收前的提醒策略见 3.12。

### 3.7 搜索、导入导出与备份

- 在单聊、群聊详情中查看和搜索历史，至少支持全部、文件、图片分类；群聊可按成员筛选。
- 使用 SQLite 作为本地正式数据存储；搜索方案考虑 FTS5，并验证中文短词检索效果，不以存在索引替代有效搜索。
- 聊天记录支持导出/导入（可按联系人选择会话与时间范围）；加密导出需设置密码，导入时正确输入密码才能读取。支持纯文本导出（在聊天记录窗口使用），具体范围及限制待确认。
- 用户备份包含恢复身份、群组与好友列表所需的数据，聊天记录可选；格式 2 起备份包含聊天图片与文件附件（附件总量上限 512 MB），恢复时还原附件并回填本机路径。完整用户备份必须设置密码，恢复必须输入密码。
- 基于 SQLite 一致性快照及成熟的密码派生和认证加密组件实现加密备份；密码错误、文件损坏或恢复失败时不得清除现有数据。
- 恢复提供增量合并和覆盖两种选择：相同消息 ID 且不可变字段一致时跳过，不同 ID 新增；相同 ID 内容冲突则停止自动合并并提示。覆盖前验证密码和完整性、保留原数据快照并取得用户确认，不同身份不得静默覆盖。恢复后更新逻辑时钟。禁止把未验证备份称为可恢复。

### 3.8 应用锁与隐私

- 提供主动锁定和临时离开锁定；应用锁密码可选，不强制用户设置。
- 可设置键盘、鼠标无操作达到阈值后自动锁定；正式实现需检测操作系统级空闲时间。
- 锁定入口在左下方，与“更多”按钮上下排列：临时离开锁定在上，三横线更多在下。
- 忘记应用锁密码时，可通过 Windows 身份验证重置，不删除聊天数据；备份密码独立，不可通过应用锁重置。Windows 身份验证的技术适用边界须在实现前验证，无密码锁定的实际解锁流程仍待明确。
- 传输加密不等于本地数据库加密；本地数据和备份的保护能力分别说明，不作超出实现的安全承诺。

### 3.9 发现与网络（局域网用户）

- 页面名称统一为「局域网用户」，不再以「身份探测 / 指纹」作为主标题与主流程。
- 同网段使用 mDNS 自动发现。候选信息包含：昵称、用户名（mDNS TXT 记录，未验证）、设备地址与端口；Qbird ID 由添加时的探测指纹派生。列表按昵称或用户名实时筛选，默认每 30 秒刷新，并提供「立即刷新」。
- 列表项显示头像、昵称、`@用户名`、在线状态与地址；已添加的联系人显示「已添加」，其余显示「添加」。点击「添加」后本机探测该地址、校验指纹与候选一致，再保存联系人；失败给出「对方离线 / 端口错误 / 网络受阻」等具体原因，不静默成功。
- 应用每次启动即自动开始监听与 mDNS 发现（默认端口来自网络设置，默认 42853），不需要用户先打开「局域网用户」页；首次引导完成后同样保持监听。
- 启动顺序：隐藏主窗口前先绑定端口；端口仍被上一个实例占用时按 300/600/900 ms 重试最多 4 次，仍失败则改用系统分配的空闲端口，由 mDNS 广播实际端口，界面显示监听中的真实端口。不得因为默认端口被占用就让应用“静默离线”。
- 监听守护：每 15 秒检查监听线程是否意外退出（崩溃、系统休眠恢复等），未经过用户手动停止且服务槽仍存在时自动在同一端口重启并重建 mDNS 广播；用户手动「停止监听」后本次运行不再自动重启，下次启动应用恢复自动监听。
- 端口被占用或监听失败时在引导页、发现页与设置页明确提示原因，并允许继续浏览其他候选。
- 其他网段与手动地址收进「其他网段与手动地址」折叠区：手动输入 `IP:端口` 添加地址；可按 /24–/32 的 IPv4 CIDR 限速扫描（最多 254 个目标、4 并发、单地址 400 ms 超时），支持黑名单。折叠区默认收起，不干扰同网段主流程。
- 支持用户配置默认监听端口、显示冲突和监听状态；修改默认端口在下次启动应用时生效，界面须写明这一点。
- mDNS 数据与地址均为未验证信息，不代表身份可信；添加时的指纹探测用于确认「这个地址确实是这个 Qbird ID」，不替代用户主动核对。
- 广播昵称与用户名属于可见性取舍：首次实现随发现广播；设置页提供关闭广播昵称/用户名的开关为后续项。设备离线、防火墙、网络隔离、禁用组播和地址变化应可诊断；不得将单次发现失败解释为对方不存在。

### 3.10 设置、导航和关于

- 采用已确认的米白轻社交视觉方向；消息、联系人、发现为左侧纵向导航。
- 左侧头像可进入个人资料；用户可设置团队 Logo 与名称，但关于页必须显示 Qbird/青鸟名称。
- 左侧底部三横线“更多”包含设置、聊天备份、用户备份、用户还原和聊天记录还原；对应未实现功能须清晰标记，不得伪装可操作。
- 设置覆盖网络、隐私、工作区、快捷键、实验功能、调试模式和关于；关于页显示版本、许可、平台和必要说明。
- 「工作区」分区包含「点击聊天图片时」（灯箱 / 右侧工作区）与「点击聊天文件时」（右侧工作区 / 默认程序）两个选项，并说明各预览类型与 Office 格式的限制，见 3.6.1。

### 3.11 插件与 Agent

- **产品方向：基础优先，扩展插件化。** 核心只保留身份、发现、聊天、基本文件交流与本地数据等必要基础能力；其他可选场景原则上通过插件增加，减少核心体积与耦合。插件接口、权限边界、故障隔离、兼容性、生命周期和数据访问必须在开放稳定 API 前设计。
- 扩展格式的侧边栏文件预览、AI Bot/Agent 对话或群聊接入是未来可选插件方向，不是当前承诺功能。Agent 方案仍需单独评估 harness、ACP 等技术路线；不得把示例误述为已实现能力。
- 当前已实现本机阶段的只读预览插件（api 1）：本地文件夹安装、manifest 校验、沙箱 iframe 与 CSP 隔离、按扩展名分派、只向插件提供被预览文件字节；编辑写回、通用插件接口、协议/消息级扩展仍待设计，详见 `docs/PLUGIN.md`。
- 插件市场暂不实施。

### 3.12 文件接收位置与接收提醒

**接收位置**

1. 单聊（含自聊）与群聊的接收目录分别独立配置，各自维护“默认目录 + 自定义目录”；未自定义时使用应用内置默认位置，两类会话的默认目录互相隔离，避免同名文件互相挤占。
2. 设置页与文件接收确认框都可“更改位置…”，调起系统目录选择器，并提供“恢复默认”。修改立即对新的接收任务生效；进行中与已完成的传输保持原路径，不迁移、不中断。
3. 路径校验：目录必须存在或可创建且可写；不可写、无权限、路径过长时拒绝保存并说明原因，不得静默回退到其他目录。不允许选择磁盘根目录、Windows、Program Files 等系统保护目录，也不允许指向程序安装目录，避免卸载或覆盖安装删除用户文件。
4. 网络共享、可移动磁盘等非本地固定盘路径可以选择，但需提示：断网、对方离线或拔出磁盘时传输失败，恢复后按断点续传重新校验；提示不作为阻止条件。
5. 接收文件仍按“消息 ID + 清洗后文件名”命名，命名规则不随目录变化而变；附件按数据库记录的实际路径访问，“打开所在目录”指向该路径。文件被外部移动或删除时明确提示“文件已移动或删除”，不得伪装成可预览。
6. 存储配额只约束应用数据目录内的附件；写到自定义外部目录的文件不计入配额，由用户自行管理磁盘空间，设置页需如实说明统计范围，不得让用户误以为配额覆盖全部接收文件。

**接收提醒**

7. 默认逐次提醒：每个接收文件（单聊与群文件一致）在写入前弹出确认，展示文件名、大小、来源（联系人，或群名 + 发送者）、目标目录与可用空间，提供“接收”“另存为…”“拒绝”。新安装默认不自动接收任何文件。
8. 记住粒度由用户在设置页选择，也可在确认框内即时选择：
   - 每次询问（默认）：全部文件逐个确认。
   - 按来源记住：对同一发送者或同一群不再询问，直接按该来源当前路径接收。
   - 全部自动接收：所有已确认联系人及所在群的文件直接接收，等价于现有“逐次确认”关闭状态。
9. 同一发送者短时间内重复提供同一文件不重复弹窗（按消息 ID 去重），待确认请求逐条平铺而不互相覆盖。当前协议为逐文件 offer，一批文件会各自生成一条待确认；合并为单次确认需要批量 offer 协议（待后续）。
10. 拒绝后该文件不再自动重问，也不重复出现在待确认列表；同一消息 ID 的重试沿用已作出的决定。待确认列表按会话展示，逐个接受或拒绝；批量接受为后续增强。
11. 提醒策略与记住的来源持久化到本机数据库，重启后保持；记住按来源长期生效，最多保留 200 个来源，可在设置页一键清除。既有安装升级后按原设置继续（原“逐次确认”映射为“每次询问”，原关闭映射为“全部自动接收”），新安装默认每次询问。
12. 接收路径与提醒策略属于本机偏好，不随用户备份迁移到其他设备，备份恢复不覆盖本机接收设置（待确认）。

### 3.13 调试模式（网络检测、网络修复与空间检测）

目标：为 beta 用户与开发者提供只读自检和有界修复，快速区分「看不到同事 / 收不到消息 / 文件发送接收失败」属于网络问题还是存储空间问题。所有检测与修复默认只作用于本机，不上传任何数据。

**入口与边界**

1. 设置页新增「调试模式」页签，与常规与网络、隐私与安全、工作区、实验功能并列；打开页签自动执行一次检测，另有「重新检测」「重新检测空间」。
2. 检测为只读：不探测他人、不修改联系人、消息、身份、接收目录或默认端口。修复仅限重启本机监听与重建 mDNS 浏览，不提供“清除数据”“重置身份”等破坏性操作。

**网络检测（只读）**

3. 显示本机平台与主机名、本机 IPv4 地址（来自系统适配器的 IPv4 地址，读取不到显示「未获取」，不推测）。
4. 显示监听服务是否运行、运行端口，并区分「已启用聊天接收」与「仅身份探测」；服务未启动时明确说明局域网用户无法连接本机。
5. 显示保存的默认端口及可用性；默认端口被本机监听自身占用时标注为「由本机监听占用」，不得误报为冲突。
6. 显示局域网发现是否已启动、当前 mDNS 候选数量；未启动或候选为 0 时给出原因提示（未打开发现、无人广播、组播被防火墙拦截）。
7. 显示已确认联系人数量，并按上述状态生成可读结论与修复建议；任何「未知 / 未获取」均如实展示，不得用推测值填充。

**网络修复（有界）**

8. 重启聊天服务：停止当前监听后，优先按原端口重新以聊天模式启动；原端口不可用时回退到保存的默认端口；两次均失败时明确告知服务已停止及原因，不得静默显示成功。
9. 重建局域网发现：丢弃当前 mDNS 浏览并重新开始，不影响监听服务自身已广播的服务记录；重建后重新统计候选数量。
10. 一键修复：依次执行重启聊天服务与重建局域网发现，并逐项显示成功或失败结果。修复不得改动身份、联系人、聊天记录、待发送消息或默认端口设置。

**空间检测（只读）**

11. 显示应用数据目录路径及其总占用、数据库文件大小、已接收附件占用与配额（含百分比）。
12. 显示单聊与群聊接收目录：是否为自定义、目录是否存在、目录占用，以及所在磁盘的可用与总容量。
13. 给出明确提示：附件占用达到配额、接收目录所在磁盘剩余不足 512 MB、接收目录不存在。提示只用于诊断，不自动删除或迁移文件。
14. 统计口径：目录占用按本地常规文件累加，不跟随符号链接或目录联接，并设置深度与条目上限；达到上限时标注为「下限」。磁盘容量读取失败时显示原因，不估算；非 Windows 平台暂显示不支持磁盘容量，但不影响网络检测。

### 3.14 截图、拖拽、粘贴与附件暂存

**截图**

1. 点击输入区「截图」后，主窗口先隐藏，再对主显示器整屏取图，并在独立的无边框、置顶、全屏窗口中等比显示该截图；用户不再看到被窗口压扁或只能在应用窗口内框选的截图。
2. 交互对齐轻量截图工具的简化版：拖动建立选区，可用八个方向手柄调整大小、拖动选区内部移动，实时显示选区像素尺寸；Enter 或双击选区确认，Esc 或「取消」放弃并恢复主窗口。
3. 确认后按屏幕缩放比裁剪为 PNG，写入应用临时目录，并作为待发送附件进入当前单聊或群聊的输入区；由用户继续补文字并点击「发送」才发出，不直接落库。
4. 未打开任何会话时点击截图直接提示先打开会话，不进入截图模式。多显示器、窗口级吸附、标注（箭头/文字/马赛克）与长截图不在本阶段范围。

**拖拽与粘贴**

5. 把文件或图片拖入窗口，等同于「选择文件/图片」：只进入输入区暂存区，显示缩略图或文件名，可逐个移除，不会在拖入瞬间入队或发送。
6. 第三方截图工具（如 Snipaste、PixPin、聊天工具自带截图）产生的临时图片文件可拖入窗口；只提供剪贴板图片的，可在输入区按 Ctrl+V 粘贴，图片同样保存为临时文件后进入暂存区。
7. 粘贴仅处理 PNG/BMP 图片且在输入区生效，纯文本粘贴保持浏览器默认行为；图片上限 16 MiB，超过时明确提示，不静默丢弃。

**暂存与发送**

8. 单聊与群聊共用同一套暂存规则：图片与文字一起发送时合成一个气泡（图片带文字说明）；文件暂不支持说明文字，文字会作为单独消息发出，界面如实说明。
9. 暂存区按会话隔离，切换会话、隐藏会话或发送成功后清空；关闭窗口、最小化到托盘不丢失未发送的暂存内容（仅保留在界面内，不做跨重启持久化）。
10. 「发送」是唯一出口：暂存内容不随拖拽、粘贴或截图自动发送；发送后进入原有的离线待发送队列，由接收方按 3.12 的提醒策略确认接收。
11. 接收侧保持「主动发送 + 被动确认接收」：发送方主动发起文件/图片，接收方按 3.12 设置逐次询问、按来源记住或全部自动接收；新安装默认逐次询问，不自动接收任何文件。

### 3.15 关闭行为与托盘

1. 点击窗口关闭按钮不再直接退出：默认弹出「最小化到托盘 / 退出 Qbird / 取消」选择框，并默认勾选「记住我的选择，下次不再询问」。
2. 选择「最小化到托盘」后主窗口隐藏，程序继续在后台运行并接收消息；系统托盘图标提供「显示主窗口」与「退出 Qbird」，左键单击托盘图标恢复窗口。
3. 记住的选择写入本机设置，重启后保持；设置 → 常规与网络 → 关闭窗口时 可在「每次询问 / 最小化到托盘 / 直接退出」之间修改，立即生效。
4. 选择「退出」才结束进程；仅隐藏窗口不停止监听与消息接收。托盘图标、关闭选择框与设置项均不随备份迁移到其他设备。

## 4. 技术与安全约束

- 技术方向：Tauri + Rust + TypeScript；Windows 使用系统 WebView2，其他平台各用其系统 WebView。网络、存储、插件接口与平台专属能力分层。
- 密码学采用成熟组件：身份密钥、TLS 1.3 双向认证、密码派生及认证加密备份；不自研密码学算法。密钥、指纹校验和异常路径需专项测试与审计。
- 通信数据需点对点加密，发现和探测只证明密钥持有，不构成信任；信任必须显式核对。TLS 握手与应用层就绪确认均完成后才发送消息。
- Windows 使用 DPAPI 保护本地身份私钥；SQLite 当前未加密，是否提供数据库加密及其密钥管理待确认。
- 不引入不必要的服务或重型依赖；开源前审查依赖许可证、版权素材、敏感数据、密钥和仓库历史。项目采用 Apache License 2.0，发布保留必要许可、版权和变更声明。
- 初步功能测试阶段应用版本只在 0.1.X 内递增；前端、Tauri、Cargo 和锁文件版本一致，并由构建检查。
- Git 为本地版本管理；远程仓库、推送与开源发布须用户另行明确授权。Git 不能替代用户数据备份。

### 4.1 安装分发形态与数据位置

**分发形态**

- 当前构建已启用安装包（`bundle.active = true`、`targets = ["nsis"]`）：`tauri build` 同时产出 NSIS 安装包与单文件 `qbird.exe`。安装包面向普通用户，含安装向导、开始菜单与桌面快捷方式、卸载入口；单文件 exe 面向内网分发和快速试用，双击即可运行。两者遵循同一套身份、数据与多实例规则。
- 运行依赖系统 WebView2：Windows 11 自带，Windows 10 多数已具备，缺失时无法启动。安装包内置 WebView2 引导；裸 exe 缺失时明确提示安装而不是静默失败。
- 安装向导按当前用户安装（`installMode = currentUser`，免管理员），默认目录为 `%LOCALAPPDATA%\Qbird 青鸟`，可改为任意当前用户可写的目录。不提供 Program Files 的“为所有用户安装”，因为安装目录同时是数据目录，受保护位置会导致数据不可写。

**数据位置随安装路径（已确认）**

- 安装版把全部本地数据放在安装目录下的 `data\`，由安装器写入标记文件 `qbird.portable` 识别，做到“装在哪里、数据就在哪里”，可连同程序整体搬移、拷贝到内网机器或放入 U 盘。
- `data\` 内包含：
  - `identity.bin`：本机身份私钥（DPAPI 保护，绑定当前 Windows 用户）
  - `qbird.sqlite3`：身份之外的本地数据，含联系人、消息、群组、设置、传输记录与配额
  - `attachments\in\`：接收的附件；自定义单聊/群聊接收位置后，新文件写入自定义目录（见 3.12）
  - `plugins\`、`stickers\`、`temp\`：插件、表情与临时文件
- 权限前提：安装目录必须对当前用户可写。安装到 Program Files、Windows 等受保护目录时，启动阶段检测到不可写应明确报错并提示改用可写目录，不得静默失败，也不得静默回退到 `%APPDATA%` 让用户误判数据位置。
- 覆盖安装（版本升级）只替换程序文件，保留 `data\`；卸载时先询问，默认保留数据，可将 `data\` 移到“文档”等用户目录或由用户显式选择彻底删除，不得静默删除身份、联系人与聊天记录。
- 从旧版本升级：首次启动若 `data\` 中没有数据库，而 `%APPDATA%\im.qbird.desktop\` 中存在完整的身份与数据库，则复制身份、数据库与表情目录到 `data\`，并保留源文件不删除；附件不复制，历史附件按数据库记录的绝对路径继续可读，界面说明其仍在原目录。迁移失败不得停留在“有数据库、无身份”的半状态，应回退到原目录启动并说明原因。
- 风险与提示：数据随安装目录意味着删除或清理安装目录会一并删除聊天数据。安装、迁移与卸载界面都必须明确说明并建议先做用户备份；备份文件默认不落在安装目录内。

**裸 exe 与便携模式**

- 未安装、直接双击运行的 `qbird.exe` 仍使用 `%APPDATA%\im.qbird.desktop\`，行为与现状一致；把 exe 拷到别处运行不会带走数据。
- 在 exe 旁放置 `qbird.portable` 标记即切换为“exe 同级 `data\`”的便携模式，供 U 盘或免安装场景使用；两种模式按数据目录隔离，各自仍只允许同一系统用户单实例运行。
- 正式对外分发前应评估代码签名，否则 SmartScreen 会持续告警（待确认）。

## 5. 页面与主要流程

### 5.1 首次使用（首次引导）

启动 → 确定数据目录（安装版为安装目录 `data\`，裸 exe 为 `%APPDATA%\im.qbird.desktop\`，安装版首次启动按 4.1 迁移旧数据）→ 安全创建或加载本地身份与数据库 → 若本机尚未完成引导，进入三步引导，完成后才进入主界面：

1. **你的资料**：昵称（必填，预填系统用户名，≤64 字符）、用户名（必填，2–20 位小写字母/数字/`-`/`_`，默认由昵称转写并去重）、邮箱（可选）、头像（可选）。显示 Qbird ID 预览。
2. **文件保存位置**：给出默认接收目录并展示可用空间与可写校验；可「更改…」调起目录选择器、「恢复默认」；展开可分别设置单聊/群聊目录。拒绝系统保护目录、磁盘根目录与程序安装目录，并说明卸载不会删除已接收文件。
3. **找到同事**：自动启动监听与 mDNS 发现，列出同网段的「可能认识的人」，可逐个「添加」或「稍后再说」；无候选时说明可能原因（对方未启动、防火墙、跨网段）并提供手动地址入口。

引导完成后写入本机 `onboarding_done`，之后启动直接进入主界面；用户可在设置中重新修改资料、用户名与接收目录。损坏身份、缺少关键数据、数据目录不可写或无法访问存储时说明原因，不静默覆盖旧数据，也不静默切换数据目录。

### 5.2 添加联系人

同网段：局域网用户页自动列出候选 → 点「添加」→ 本机探测并校验候选指纹 → 保存为联系人 → 向对方发送「联系人通知」，对方自动把本机加入联系人（可在设置关闭自动接受）→ 双方可直接聊天。对方离线时通知延后到下次打开单聊时重试。

其他网段：展开「其他网段与手动地址」→ 输入地址探测或扫描网段 → 从结果添加。完整指纹核对作为可选增强：进入联系人或候选的「身份详情」，双方通过独立渠道核对完整指纹后标记为「已验证」。

### 5.3 单聊与自聊

单聊：选择已确认联系人 → 显示连接状态 → 编辑并发送 → 本地记录与对方接收确认 → 在消息列表显示。自聊：从联系人打开自己 → 本地发送与保存 → 在消息列表显示，不依赖局域网在线。

### 5.4 隐藏和恢复会话

对任意自聊/单聊/群聊选择隐藏 → 从消息列表消失，消息和联系人保留 → 由联系人重新打开或有新消息时重新显示。入口及未读处理以最终确认的交互为准。

### 5.5 备份与恢复

选择用户备份及是否包含聊天记录 → 输入密码 → 生成可验证的加密备份；恢复时先验证密码与备份完整性，选择增量合并或覆盖。覆盖前保存快照并经明确确认；同 ID 冲突不得自动合并。失败不得破坏现有数据。

### 5.6 接收文件

对方发送文件 → 本机按提醒策略弹出确认（文件名、大小、来源、目标目录与可用空间）→ 选择接收、另存为或拒绝 → 接收后写入目标目录并校验完整性 → 气泡显示进度与完成，可从气泡或右侧工作区打开所在目录。可在设置页预先设置单聊与群聊的接收目录，或调整提醒策略为按来源记住或全部自动接收。

### 5.7 调试与自检

设置 → 调试模式 → 自动显示网络与空间检测结果 → 根据提示选择「重启聊天服务」「重建局域网发现」或「一键修复」→ 修复后自动重新检测并显示每步结果。若问题指向存储（配额已满、磁盘剩余不足、接收目录不存在），按空间检测中的路径与容量提示处理，调试模式本身不删除文件。

## 6. 阶段计划与验收

阶段顺序可调整；测试版本始终保持 0.1.X。每阶段完成需有可复现的构建、自动化结果、关键用户路径及异常场景证据。

| 阶段 | 目标 | 最低验收 |
|---|---|---|
| A：身份与发现 | 身份持久化、mDNS/手动探测、双方独立核对 | 重启身份不变；不核对不授信；双机实际验证；异常不覆盖数据 |
| B：可用文字会话 | 已确认联系人加密单聊、本地消息、自聊、消息列表与隐藏 | 双机交换消息、重启记录保留、失败有提示；自己存在、无网络自聊；三类会话隐藏不删记录，新消息重新显示 |
| C：资料与基础体验 | 个人资料、联系人管理、必要设置、原型还原 | 头像裁剪/昵称保存、分组与备注、窄窗口可用，未实现功能有明确提示 |
| D：文件与群聊 | 图片文件、续传、群聊与群文件 | 中断恢复及完整性验证；群成员权限、@、引用跳转与群成员变动在多机验证 |
| E：记录与安全管理 | 搜索、导入导出、备份恢复、应用锁 | 中文查询测试；密码错误/损坏时数据不丢失；备份在干净环境验证恢复；锁定行为和风险提示正确 |
| F：跨平台与扩展 | 插件接口、Linux/macOS、开源准备 | 平台适配及互通测试、插件边界测试、依赖/版权/敏感信息及安全审查；Agent 另行立项 |

涉及文件和群聊的验收不以单机模拟代替真实双机或多机验证；实际排期和各阶段版本号未确定。

## 7. 非功能需求

- **安全**：采用成熟密码组件、最小权限和明确的错误处理；敏感内容不得泄露到日志或版本库。对尚无能力的安全属性不得宣传为已实现。
- **可靠性**：身份和历史数据损坏时拒绝静默覆盖；断电/断网、恢复失败、重复消息和低磁盘空间均有测试和清晰提示。
- **隐私**：局域网发现信息按最小必要原则暴露；IP/MAC 与身份指纹的展示范围可控。网络功能不隐式上传聊天数据。
- **性能**：优先轻量、低依赖，发现与文件传输资源有界；具体延迟、吞吐、内存、附件大小和设备规模指标待基准测试后确定。
- **兼容与可用性**：Windows 首发，后续 Linux/macOS；窄窗口、系统缩放、键盘操作及重要错误提示需验证。
- **可维护性**：可测试的接口边界、版本一致性和 Git 历史；不将密钥、数据库、日志、依赖目录、构建产物提交到版本库。

| 旧版迁移 | 从 `%APPDATA%` 升级到安装版时复制身份、数据库与表情，源文件保留；历史附件仍可从原路径打开；迁移中断不得出现有库无身份的半状态 |
| 搜索与备份 | 文件/图片/全部及群成员筛选正确；加密备份错误密码、损坏文件不清除现有数据 |
| 调试模式 | 网络检测显示监听/端口/发现/地址状态且不修改任何数据；重启服务后按原端口或默认端口恢复并可收发；重建发现后候选重新出现；空间检测显示附件占用、数据库大小与接收目录磁盘余量；配额已满、磁盘不足、目录不存在均有提示；磁盘容量不可读时不虚构数值 |
| 安全与跨平台 | 传输内容和身份校验符合设计；各平台密钥保护、系统空闲和窄屏行为经实际验证 |
